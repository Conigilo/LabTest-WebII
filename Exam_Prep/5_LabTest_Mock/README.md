# 🎯 โครงสร้างโปรเจกต์มาตรฐานสำหรับ Lab Test

ในการสอบแบบ **Lab Test (ปฏิบัติ)** อาจารย์มักจะให้คะแนน "ความสะอาดและการจัดระเบียบโค้ด (Clean Code & Architecture)" ด้วย! ถ้าคุณเอาทุกอย่าง (Routes, Database, Logic) ไปยัดรวมใน `app.js` ไฟล์เดียว โอกาสโดนหักคะแนนสูงมาก

เพื่อความปลอดภัยและได้คะแนนเต็ม ผมแนะนำให้แบ่งโฟลเดอร์ตาม **MVC Pattern (Model-View-Controller)** แบบย่อดังนี้ครับ:

```text
Exam_Prep/5_LabTest_Mock/
├── config/
│   └── db.js         (เก็บการตั้งค่าเชื่อม Database เช่น SQLite/Prisma)
├── controllers/
│   └── bookController.js (เก็บ Logic ล้วนๆ เช่น ดึงข้อมูล ค้นหา บันทึก)
├── routes/
│   └── bookRoutes.js     (เก็บ Path URL เช่น /api/books แล้วเรียกใช้ Controller)
├── app.js            (ไฟล์หลัก: เอาไว้ผูก Express เสียบ Swagger และโยงไปหา Routes)
└── package.json
```

### 🧠 เทคนิคการทำ Lab Test ให้เซฟและไวที่สุด!

1. **ทำโจทย์จากล่างขึ้นบน (Bottom-up Approach)**
   * เริ่มจากตั้งค่า DB (ชัวร์ว่าเชื่อมติด) -> เขียน Controller (ทดสอบ Logic) -> เขียน Route -> ผูกเข้า `app.js`
2. **"Postman คือเพื่อนรัก"**
   * เวลาเขียนแต่ละ Endpoint ดึงข้อมูล (GET), เพิ่ม (POST) ให้ทดสอบด้วย Postman **ทุกครั้ง** อย่าเขียนรวดเดียว 10 เส้นแล้วค่อยเทส เพราะถ้าบัคมันจะหาจุดผิดยากมาก
3. **ใช้ `nodemon` ตอนสอบเสมอ**
   * จะได้ไม่ต้องมากดปิด-เปิดเซิร์ฟเวอร์ใหม่ทุกครั้งที่แก้รันโค้ด (`nodemon app.js`)
4. **ทำของง่ายก่อน**
   * ถ้าโจทย์มี 5 ข้อ (GET, POST, PUT, DELETE, ค้นหา+เรียงลำดับ) ให้ทำ GET กับ POST ก่อน และทดสอบ Swagger ให้ขึ้นจอ เพราะเป็นส่วนที่ได้คะแนนชัวร์ๆ ค่อยไปทำ Logic ยากๆ ทีหลัง
