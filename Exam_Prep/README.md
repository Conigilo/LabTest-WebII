# 📚 คู่มือติวสอบ: การพัฒนา Web API ขั้นสูง

ยินดีต้อนรับสู่โฟลเดอร์สำหรับติวสอบ! เราได้แยกหัวข้อที่คุณจะสอบในวันพรุ่งนี้ออกเป็น 4 โฟลเดอร์เพื่อให้คุณทำความเข้าใจได้ง่ายๆ ทีละสเต็ป พร้อมตัวอย่างโค้ดที่รันได้จริง 

### สรุป 4 หัวข้อหลัก (Concept แบบสั้นๆ)

1. **REST API + Swagger (โฟลเดอร์ `1_REST_Swagger`)**
   * **REST API:** คือรูปแบบสถาปัตยกรรมสำหรับส่งข้อมูลหากันแบบ HTTP (ใช้ Method GET, POST, PUT, DELETE) เรามักใช้โต้ตอบและส่งข้อมูลในรูปแบบ `JSON`
   * **Swagger:** คือเครื่องมือสำหรับ "เขียนเอกสารกำกับ API (API Docs)" ช่วยให้หน้าตา API น่าอ่าน ทดสอบง่าย (UI สวยๆ) โดยการระบุผ่านไฟล์ `.yaml` หรือ `.json`

2. **gRPC (โฟลเดอร์ `2_gRPC`)**
   * **gRPC:** คือวิธีการส่งข้อมูลของ Google ที่เร็วกว่า REST API ทำงานผ่านโปรโตคอล HTTP/2 ส่งข้อมูลทางท่อเล็กๆ (Binary) แทนที่จะเป็น String
   * มีไฟล์สัญญา `.proto` เป็นตัวบอกว่าฝั่งรับ/ส่งคุยกันด้วยโครงสร้างอะไร หน้าที่ของโปรแกรมเมอร์แค่เขียน Server/Client มารับส่งกันเอง (ตามสัญญา)

3. **ORM - Object-Relational Mapping (โฟลเดอร์ `3_ORM`)**
   * **ORM:** คือเครื่องมือที่ช่วยให้เรา "คุยกับ Database ผ่านโค้ด Javascript/TypeScript (หรือภาษาอื่น)" แทนที่จะต้องพิมพ์คำสั่ง `SQL (SELECT * FROM users)` ยาวๆ 
   * เราสามารถใช้ `prisma.user.findMany()` ได้เลย มันช่วยลดการเขียนโค้ดและช่วยกันภัยจาก SQL Injection (ตัวอย่างนี้เราจะใช้ `Prisma` เพราะฮิตมาก)

4. **Authentication & Authorization (โฟลเดอร์ `4_Auth`)**
   * **Auth:** ระบบยืนยันตัวตน มีหลายแบบ (เช่น Session/Cookie, JWT) 
   * ปัจจุบันฮิตใช้ **JWT (JSON Web Token)** มากที่สุด หลักการคือ: User ส่ง Username/Password มา -> Server ตรวจสอบว่าถูกไหม -> ถ้าถูก ส่งกุญแจ (Token) ให้ User เอาไปแนบตอนจะเข้าถึงข้อมูลลับ
